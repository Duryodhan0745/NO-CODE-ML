# Workflow inventory (repository audit)

This inventory reflects `frontend/src/Workspace.jsx`, `backend/main.py`, `backend/services.py`, `backend/ml.py`, and `backend/optimizer.py`. The frontend has eleven ordered stages after the column selection addition. There is no LangGraph `StateGraph` in the repository; `backend/ai/orchestrator.py` uses a provider-backed bounded loop and an allowlisted `ToolRegistry`. Workspace state is JSON-backed in `backend/state/workspace_state.json`; AI conversations, events, memories, tool executions, and approvals are SQLite-backed by `backend/ai/persistence.py`.

## Stage inventory

| Stage / ID | Inputs and supported values | Validation and execution | Outputs and dependencies | Cost, state, and failure conditions |
|---|---|---|---|---|
| Dataset upload / `dataset_ingestion` | CSV file, filename; upload-size and extension limits from config | `POST /api/datasets/upload` → `services.upload_dataset`; parse, non-empty data and unique column checks | Dataset id, row/column counts, dtypes, missing and duplicate counts, validation checks. First stage; feeds all later stages. | Reads/writes full uploaded file; creates original dataset record. Fails for invalid extension, size, parse or empty/duplicate columns. |
| Preview / `dataset_preview` | Dataset id, 1–200 preview rows (default 20) | `GET /api/datasets/{id}/preview` → `services.get_preview`; dataset id must exist | Sample rows and column list. Depends on ingestion. | Reads CSV and returns bounded rows; no dataset mutation. Fails when dataset is missing or unreadable. |
| Analysis / `eda` | Dataset id | `GET /api/datasets/{id}/analysis` → `services.get_analysis` | Descriptive numeric summaries, categorical top values, missingness, correlation, duplicate count, file size. Depends on ingestion. | Full-file scan and numeric correlation. No state mutation except workflow event. Fails on missing/unreadable dataset or analysis error. |
| Target and task / `target_problem` | Target column; classification or regression | UI selection; `services.configure_workspace` validates target existence/cardinality, numeric regression target and supported task | Target/task selection; feeds model list, preprocessing validation, configuration, training. | Low computation; no backend mutation until configure. Unsupported tasks, invalid target and single-valued target fail validation. |
| Remove unnecessary columns / `column_selection` | Retained column list and optional selected target | `GET /api/datasets/{id}/columns`; `POST /api/workspaces/{id}/column-selection`; `services.get_column_statistics` and `services.apply_column_selection` | Dataset-grounded column statistics and role explanations; retained/removed columns, new dataset id/schema/version/fingerprint. Target must remain and one feature must remain. | Full CSV read/write. Original upload stays intact; a deterministic transformed CSV becomes the workspace dataset. Errors include unknown/duplicate/empty selection or target removal. Restore endpoint returns workspace to original dataset. |
| Preprocessing / `preprocessing` | Missing strategy: mean/median/mode/drop; scaling none/standard/minmax; SMOTE classification only; PCA and component count supported by `backend/ml.py`; outlier checkbox is currently UI only | Chosen in UI; passed to `services.configure_workspace`; transformations run through `build_preprocessing_pipeline` during training | Actual transform details and config are saved with training run, not as a separate preprocessing execution. Depends on selected dataset, task and target. | Training-time transform fit on training split only. Unsupported config, incompatible SMOTE or missing data failures surface during config/train. UI outlier control is not implemented in backend. |
| Model selection / `model_selection` | Registered classification/regression model ids from `MODEL_REGISTRY` | `GET /api/models?problem_type=...`; validates compatibility in `services.configure_workspace` | Selected model and registry parameter schema. Depends on task type. | Registry listing is cheap. Unknown or incompatible model fails configuration. |
| Model parameters / `model_configuration` | Model parameters from each registry entry; parameter defaults and validation in `create_model` | UI fields; `POST /api/workspaces/{id}/configure` → `services.configure_workspace` dry-runs model construction | Persisted target, task, preprocessing, model id and params; invalidates previous metrics, artifacts and optimization. | Low validation cost. Invalid model parameters or incompatible dataset/task fail. Mutates workspace config. |
| Train / `training` | Configured workspace; split uses configured constants (test size and random state) | `POST /api/workspaces/{id}/train` → `services.train_workspace`; existing classifier/regressor, preprocessing pipeline and optional SMOTE | Run id/status, held-out metrics, predictions, model/preprocessor/metadata/config artifacts and training metadata. Depends on successful configuration. | Dataset-sized transform and model fit; may be costly. Fails if not configured, split/model/preprocessing fails, or resources are exhausted. Mutates status and run history. |
| Evaluation / `evaluation` | Completed training run | `GET /api/workspaces/{id}/evaluation` → `services.get_evaluation`; classification metrics/confusion matrix or regression metrics | Actual persisted metrics. Depends on training. | Reads stored results; unavailable before training. |
| Hyperparameter optimization / `optimization` | Strategy optuna/bayesian/grid/random; candidate model ids; metric; trials/iterations; CV folds; timeout; optional parameter grid | `POST /api/workspaces/{id}/optimize` → `services.optimize_workspace` and `backend/optimizer.py` | Search history, best model/params/score, run metrics and artifacts. Depends on target/task/configuration. | Approximate workload is candidates × trials × folds for trial-based searches; timeout/search validation can fail. Mutates optimization and run state. |
| Prediction / `prediction` | CSV with trained feature columns | `POST /api/workspaces/{id}/predict` → `services.predict_workspace`; validates missing feature columns and reports ignored extras | Persisted prediction CSV and download URL. Depends on a trained model and compatible columns. | Cost scales with prediction rows and preprocessing/model. Fails for missing features, invalid values, absent artifacts. |

## Supporting workflow operations

Correlation and VIF are read-only analysis endpoints; profiling creates a report and can be expensive. Workspace run history, artifact listing/download, optimization result, authoritative AI workflow context, and stage event reads are also available. The model registry contains the algorithms and exact supported parameters; the backend accepts only classification and regression. Forecasting and clustering are not implemented as executable ML tasks.

## Cross-cutting findings and gaps

- Tool handlers are allowlisted and call existing backend functions; arbitrary code/shell/SQL tools are absent. `ToolRequest` is strict at its top level, while tool-specific arguments remain generic dictionaries and are validated primarily by services.
- AI ownership checks apply to AI routes; the traditional ML API routes do not currently authenticate workspace access. `OPEN_ACCESS_MODE` supplies a fixed local testing principal and does not create production authentication.
- `workflow_proposals` persists each three-choice proposal with its user, workspace, stage, configuration fingerprint, dataset version, workflow version, expiry, decision and execution result. The decision service atomically claims an awaiting proposal before YES runs, preventing replay. It records `rejected` for NO and `filled_only` for JUST FILL; stale dataset/workflow/fingerprint and expired proposals are rejected. `draft` and `validating` are contract states, while validation currently occurs before the record is created as `awaiting_approval`.
- The AI companion displays exactly three primary actions for an awaiting proposal. YES executes through the existing service, NO preserves workflow state, and JUST FILL copies values into the editable existing target, preprocessing, model, parameter, or column-selection controls without an execution call. Traditional manual `/train` and `/optimize` remain direct user-operated paths.
- `estimate_resources` reports measured rows, feature count and file size where available, plus approximate memory/workload. Runtime remains unavailable when the system cannot measure it. Configurable hard resource limits are still absent.
- Column recommendations are conservative metadata heuristics (constant, exact duplicate, high missingness, near-constant, high cardinality); they cannot infer objective/domain relevance or prove target leakage. They give explicit review reasons and never remove columns automatically.
- Output contracts include a shared typed envelope and stage-specific models in `backend/ai/contracts.py`. Consequential column-selection, configuration, training and optimization endpoints add a compatibility-preserving `workflow_output` envelope. Read-only endpoints and older events retain their established response shapes.
